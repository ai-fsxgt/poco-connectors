# Agent 平台使用数据

数据来自连接器工具 `get_usage_dataset`，需要使用管理员账号授权。本技能提供数据采集方法和思路，按用户需求提取数据，不自动生成 HTML 页面或执行固定的报告流程。

## 获取数据

- 确定用户要查询的日期区间，按北京时间计算，起止日期均包含在内。相对日期以当前北京时间为准，本周从周一开始。
- 调用 `get_usage_dataset`，参数只有 `start_date`、`end_date`，格式为 `YYYY-MM-DD`。单次最多 31 天；更长的采集区间可拆为互不重叠的区间分别查询。
- 工具返回汇总信息，并将完整数据集作为压缩 JSON 文件交付到工作区。使用返回的 `workspace_path` 读取文件；资源 URI 不是本地文件路径。

用 Python 标准库读取压缩文件，按需求选择字段，避免把全部工作项打印到上下文：

```python
import gzip
import json

with gzip.open(dataset_path, "rt", encoding="utf-8") as file:
    dataset = json.load(file)

print(json.dumps(dataset["totals"], ensure_ascii=False))
```

`dataset_path` 使用工具实际返回的 `workspace_path`。

## 数据结构与采集思路

| 数据字段 | 内容 | 采集思路 |
| --- | --- | --- |
| `totals` | 当前区间的运行次数、完成/失败/取消次数、会话数、活跃用户数、美元成本及输入/输出 Token | 获取平台整体用量与消耗 |
| `previous_totals` | 紧邻当前区间之前、相同天数的汇总 | 与当前区间对比；不要将其当作当前区间的数据累加 |
| `days` | 按天的运行、失败、取消、活跃用户、成本及 Token | 观察逐日变化，查找高消耗或失败集中的日期 |
| `users` | 用户 ID、姓名、部门、运行次数、失败次数、工作项数、成本与首次运行时间 | 按用户或部门汇总用量和成本；这里仅包含区间内有运行记录的用户 |
| `work_items` | 工作项 ID、触发方式、用户 ID、内容可见性、标题、摘要、首条请求、分支标记、运行状态计数、活跃天数、成本、Token 和首末运行时间 | 查询具体工作项，或按触发方式汇总运行与消耗 |

- `work_items.trigger` 的值为 `scheduled`（定时任务）、`chat`（人工对话）、`api`（API 会话）、`embed`（嵌入会话）。
- 用 `work_items.user_id` 与 `users.user_id` 关联部门；部门为空时如实保留为空，不根据姓名、标题或内容猜测。
- 只有 `content_visible` 为真时才使用标题、摘要和首条请求判断用途。隐私内容仍参与数值统计，不能推测其具体用途。
- 跨区间汇总时，运行、成本与 Token 可按互不重叠的区间累加；活跃用户需按 `user_id` 去重，工作项需按 `item_id` 合并，不能直接累加各区间的数量。数据集不包含会话 ID 清单，跨区间会话数不能直接相加当作去重总数。
- `users` 只有活跃用户，无法据此计算全部注册用户或全部门的渗透率；成本单位是美元。失败次数与取消次数分开统计，计算比率时说明分子、分母，分母为零时不输出有效比率。

## 错误处理

- 授权失败时如实返回错误，提示用户在连接器中使用管理员账号重新授权。
- 日期区间无效或响应超过大小上限时，根据工具错误调整查询区间，不把错误当成空数据。
- 其他接口错误如实说明，不用零值或虚构数据代替。按用户需要返回采集结果与统计口径，不预设展示格式或分类体系。
