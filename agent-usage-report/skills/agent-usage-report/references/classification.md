# 工作项分类规则

每个工作项组给出两个代码，格式为 `业务领域/产出物`，例如 `quality/alert`。代码清单和提示词写在 `items.md` 开头，以那里为准。

业务领域对照公司业务架构，分为四个板块：

| 板块 | 业务领域 |
|---|---|
| 生产 | 生产管理、高炉、烧结、竖炉、炼钢、轧钢 |
| 供销 | 供应、废钢、销售、深加工 |
| 专业管理 | 质量、设备、能源、安环、财务、人事 |
| 综合 | 执行力与知识管理、对标与研究、AI 平台建设、其他 |

## 判断依据

**描述**：AI 会话摘要；没有摘要时，用户的首条消息，以「[用户提问]」开头。描述说明了用户实际要做什么、交付了什么，最可靠。

**标题**：描述含义不清时作为补充。

**触发方式**：只用来辅助判断，不能单独决定分类。

判断的是「为哪项业务产出了什么」，**不是 Agent 用了什么工具**。几乎所有任务都会写代码、跑脚本、读写文件，这些都不代表在做软件开发。

## 业务领域

- **选工作内容所服务的业务，不选用户所在部门。**
- **具体工序优先**：内容只涉及某一个工序时，归该工序（高炉、烧结、竖炉、炼钢、轧钢）。跨工序或全厂层面的生产日报、库存、产量、调度、停机，才归 `production_mgmt`。
- **质量问题归 `quality`**：原料或成品的质量异常、检化验结果都归质量，即使涉及具体钢种或工序。
- **能源问题归 `energy`**：用电、煤气、蒸汽、水、碳排放都归能源，即使发生在某个工序里，例如「高炉煤气放散」。
- **财务**：成本对标、改良改善提报及其审核、报支公文、合同审核，归 `finance`。
- **人事**：规章制度、红线标准、管理细则的查询，归 `hr`。
- **对标与研究**：外部行业、标杆企业、技术路线的调研，归 `benchmarking`。只研究钢价、出口、市场需求的，归 `sales`。
- **AI 平台建设**：平台自身的工作归 `ai_platform`，例如创建或测试技能、连接器授权、Agent 培训材料、Agent 使用分析。
- **信息不足一律用 `other`，禁止猜测**：标题是「执行任务」「User provided non-text input blocks」这类系统占位文字，描述又看不出业务时，直接归 `other/other`。

## 产出物

产出物**按最终交付物判断**。

- **`alert`**：按规则检测异常并推送给人。检测窗口内没有异常、本次没有推送的，仍然归 `alert`。
- **`report`、`dashboard`、`app` 的区别**：
  - 一次性的分析结论、定期日报周报月报，归 `report`。
  - 以展示数据为主、固定格式、反复刷新的页面，例如看板、监控页、价格展示页，归 `dashboard`。
  - 需要用户输入或操作才能完成业务的，例如录入、登记、计算、审批流转，归 `app`。
- **`app`**：交付了可反复使用的交互工具，例如小程序、管理系统、计算器、录入页面。没有描述时，标题含「系统」「小程序」「计算器」「页面」「平台」的，按 `app` 处理。为了出报告而写的脚本不算 `app`，按它最终产出的报告或数据判断。
- **`review`**：针对某一份具体的提报、合同、单据给出审核意见。交付的是一份完整分析报告的，归 `report`。
- **`data_sync`**：交付物是数据本身，例如把数据写入系统、导入报表、整理成 Excel。
- **`debug`**：
  - 带【分支】标记、且描述显示在修复、排查、测试或调整原任务配置的，归 `debug`，业务领域沿用原任务的领域。
  - 带【分支】标记，但做的是新增功能、或产出新的报告与工具的，按新的交付物分类，不归 `debug`。
  - 没有分支标记，但描述明确是在排查、修改配置、测试的，同样归 `debug`。
  - 「发送测试消息」「演示某技能用法」「安装或认证某技能」这类，归 `ai_platform/debug`。
- **`qa`**：只查询、咨询，没有形成文件或页面。
